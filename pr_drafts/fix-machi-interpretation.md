# 和了牌が入り得る待ちを全部試す

ブランチ: `fix/machi-interpretation`

## 何が誤りか

和了の形の 1 つの分け方について、`MachiJudge` は最初に当たった待ち（雀頭、次に面子の順）だけを返します。
和了牌は複数の待ちに入り得て、手は最も高くなる取り方で数えるものです。

- `123s 345m 123p 345p 55m` を 5m で自摸: 5m は単騎（雀頭 55m）にも両面（34m + 5m）にも取れます。両面なら平和が付きます
  （20 符）が、エンジンは単騎（30 符、平和なし）で数えます。
- `567p 123s 678p 444z 99s` を 7p で自摸: 両面（56p）にも嵌張（68p）にも取れます。嵌張なら 40 符ですが、エンジンは 30 符です。

## 再現

`machi_judge_spec.rb` と `win_evaluator_spec.rb` の spec。

## 直し

`MachiJudge.regular_machi_types` は分け方ごとに取り得る待ちを全部返し、`WinEvaluator` と `RoundFlow.can_agari?` は
それぞれを試します（`WinEvaluator` はもともと分け方の中でいちばん高い点を採ります）。`find_machi` は同じ牌・
同じ形に複数の結果を返すことがあります。`tenpai?` と `machi_tile_indices` は変わりません。

## 互換性

一部の和了の点が上がります（平和が付く、符が上がる）。Python の `mahjong` パッケージとの突き合わせで見つけました。

---

和了牌が単騎にも両面にも（両面にも嵌張にも）取れるとき、最初の 1 つしか見ず、平和や高い符を逃していた。取り得る待ちを全部試して高い方を採る。
